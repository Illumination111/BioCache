# 当前 LIF 存储实现、瓶颈与改进目标

## 判断

目前不能把失败主要归因于“LIF 神经元数量不够”。本次新增的三种子探索性对照中，每列 32、64、128 个神经元均只有 3/24 个非零延迟条件达标，增加数量没有解决整体失败。更明确的问题是当前读取结果对 Query 不敏感、Key–Value 关联尚未充分学会、持续干扰导致误差显著增大。

这不证明神经元数量永远足够。容量、编码、传播、读出能力和优化进度是不同因素。当前实验没有把这些因素完全分离，也没有找到充分训练后的容量上限。

本文依据当前 SpikingJelly 实现、已保存的三种子实验，以及本次新增的容量和 Query 选择性诊断。主实现没有改动。容量对照新增运行9组训练、复用3组现有基线；所有新训练沿用100步协议。属于探索性分析，没有显著性检验，也复用了原评估集，不是新独立测试集上的确认试验。

## 存储对象和结构

当前存储对象是合成的逐 token K/V，没有加载真实 VLM。默认单层、一个 KV/Query head、head dimension为8，每段历史8个token。基础模块可建立多层阵列，但当前质量实验仅检验一层。

每个 Transformer 层对应一片独立阵列，每片4列，每列64个LIF神经元，所以每个样本、每层共有256个神经元。batch size 32是32份独立状态，不是一个样本共享8192个神经元。

```text
本层 token K/V → 本层编码器 → 列0 → 列1 → 列2 → 列3
                                相邻列稠密连接
```

每对相邻列有64×64个可训练权重；每层共3×64²=12,288个列间权重。没有同列横向连接、反向、跳列或跨层连接。神经元自己的时间保持属于膜电位动力学。

持久状态为：

| 字段 | 形状 | 当前 dtype | 用途 |
|---|---|---|---|
| u | [B,L,C,N] | FP32 | 软重置后的膜电位 |
| spikes | [B,L,C,N] | FP32，取值0/1 | 当前微步脉冲，供下一步传播和读取 |
| time | [B,L] | FP32 | 已推进的事件时间 |
| events | [B,L] | int64 | 推进的事件数量，含零输入等待 |
| valid | [B,L] | bool | 是否有有效写入 |

没有历史KV列表、历史脉冲列表或重建出的完整KV缓存。完整KV仅由实验教师保留，供监督和计算参考输出。

## 输入编码：K/V 如何写入

每个token将本层所有KV heads展平并拼接，附加两项因果位置/时间特征：

```text
raw_t = concat(vec(K_t), vec(V_t), sin(position_t/16), sin(time_t/16))
x_t = Linear_l(raw_t)
```

默认输入18维，线性映射到64维首列电流。电流可以为负，没有ReLU强制截断。编码器没有接收未来Query或答案；未来Query仅用于训练监督和读取。

这还是简单的KV联合线性投影，没有显式的按Key寻址、K/V乘性交互或事件保护机制。默认匀速输入时position和time相同，两项正弦特征实际重复；真实帧/patch语义位置、非均匀时间和多尺度位置编码尚未实现。

## 列传播和保持

每个token是一件外部事件，执行4个内部微步，总时长1，因此dt=0.25。仅第一个微步向首列注入当前token电流，其余微步首列外部输入为零。相邻token之间不额外flush。

```text
I_0 = x_t，仅事件首微步；其他微步为0
I_c = W_(c-1) @ spikes_old_(c-1)，c>0
u_pre = exp(-dt/tau) * u_old + I
spikes_new = H(u_pre - threshold)
u_new = u_pre - threshold * spikes_new
```

所有列读取旧脉冲后同步更新，不按列原地串行穿透。零状态的孤立脉冲最早在第1/2/3/4个微步影响各列。S=C保证时间上允许到达末列，不保证真实带符号KV一定触发传播。

实际充电、发放、软重置和代理反向由SpikingJelly官方ParametricLIFNode与ATan完成，使用torch后端。物理tau转换到库的衰减参数，电压和电流按可训练阈值归一化。库内部节点每次调用后reset，清理的是内部临时副本；已经返回的外部u/spikes仍保留，存储不会因此被清空。详情见[读取与算子说明](readout.md)。

tau按列初始化为16/64/256/1024，阈值初始化为0.5，之后每个神经元可独立学习。停止写入时仍推进泄漏和脉冲传播；输入干扰时同样更新所有神经元，没有自动保护旧事件。

重要区别：跨列传输的只有脉冲，不是前列膜电位。因此首列中存在的负值、亚阈值信息，不一定以足够可辨识的脉冲模式传入末列。大N会增加通道数，但不会自动消除阈值编码和传播损失。当前每微步至多发放一个0/1脉冲；软重置不把电位限制在阈值以下，强输入可留下较大残余电位。固定状态字节数不等于膜电位幅值也有界。

## 如何读取

主要读取当前层末列：

```text
z = concat(u_last, spikes_last)       # [B,128]
h = SiLU(Linear(z))                  # [B,64]
packed = Linear(h)                  # [B,64]
K_latent, V_latent                   # 各[B,1,4,8]
Y_hat = softmax(Q @ K_latent.T / sqrt(8)) @ V_latent
```

128维特征由64个连续膜电位和64个二值脉冲组成，不能视为128个独立连续存储通道。MLP不接收Query，生成的4组latent K/V只由状态决定；Query在最后一步attention中选择信息。

这些是学习出的摘要槽位，不对应原始8个历史token，不保证重建原始KV。读取不修改状态和时间；空状态返回零。首列和全列使用独立读出器做对照；全列输入512维，参数更多。另有不使用Query的MLP Value探针，用于诊断事件Value或末token Value是否保留。

读取槽位也有自身容量限制。单head、固定状态下，所有Query的输出都落在4个latent Value的凸包内，其仿射维数至多为3。一般8个8维历史Value的凸包仿射维数可以为7。因此，4槽位无法在一般情况下精确表达8个独立历史Value对应的全部Query输出。这是当前读出结构的限制，不是对本次单Query误差原因的完整证明；即使增加神经元也不会改变这个4槽位限制。

## 目前如何训练

四类数据分别是低秩背景、随机关联、短暂唯一事件、相似Key/不同Value。每步使用新序列，训练batch为32；训练100步，每类仅25步。Adam学习率0.002。

教师用原始8个KV计算标准attention。学生的历史写入不可见未来Query，但训练可以用未来Query的目标反向监督历史编码。

当前每段历史只采样一个监督Query。分别训练首列、末列、全列读出器，并把三者的attention MSE和Value探针MSE等权平均。辅助探针偏向预设事件或末token Value，未必与任意Key关联读取目标完全一致；多个读取位置也同时影响共享编码器与阵列。

训练延迟为0/4/16，最长序列24个事件；配置的TBPTT间隔32在这些默认训练序列内部没有触发。测试延迟0/16/64/256，后两种是训练分布外的延迟。因而长延迟失败不能直接等同于状态容量不足。还没有训练到收敛或建立充分的训练预算对照。

## 内存口径

当前运行态字节数为`8*B*L*C*N + 13*B*L`。默认单样本单层为2061字节，其中u和spikes各1024字节，元数据13字节。spikes实际为FP32，不能按bool计算。

8-token教师历史只有`2*8*1*8*4 = 512`字节，因此当前短历史质量实验没有实现相对这段KV的状态压缩：LIF状态约为其4.03倍。静态模块有126,745个参数、506,980字节，连接mask为12字节，全部诊断读出/探针加持久状态共509,053字节。

长流状态字节数在1000/10000事件保持2061，是有界性证据；这个检查用新初始化的模型，不是长流存储质量验收。10000事件完整KV为640,000字节，只有缓存口径比值约310.5；把本项目所有新增静态模块计入后，640000/509053约为1.26。临时激活、框架和真实VLM权重还未包含，不能宣称端到端压缩310倍。

## 新增容量对照：神经元数是否不足

保持4列、4微步、训练100步、相同数据生成种子和测试序列不变。每项用11/22/33三个种子；基线复用既有SpikingJelly结果，其余重新训练。读出hidden width仍为64。

| 每列N | 总神经元 | latent槽位 | 状态字节 | 短延迟末列MSE | 256事件等待MSE | 256事件干扰MSE | 达标条件 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 32 | 128 | 4 | 1037 | 0.5281±0.0291 | 0.5298±0.0293 | 3.2754±0.7584 | 3/24 |
| 64 | 256 | 4 | 2061 | 0.5118±0.0276 | 0.5150±0.0291 | 3.8341±0.2192 | 3/24 |
| 128 | 512 | 4 | 4109 | 0.5155±0.0204 | 0.5104±0.0282 | 3.1841±0.6175 | 3/24 |
| 64 | 256 | 8 | 2061 | 0.5201±0.0291 | 0.5227±0.0283 | 2.5005±0.5466 | 3/24 |

数值为先在每个种子内对四类数据等权平均，再计算三种子的均值±样本标准差。短延迟是0/16两种测试延迟与两种输入模式的平均。完整分数据条件结果和全部读取位置保留在[容量诊断证据](../experiments/lif_kv_feasibility/results/capacity_diagnostics/)。不能用这个总体平均替代逐条件验收。

直接结论：在当前100步训练协议中，N从64翻倍到128没有改善短延迟平均误差或达标数量。干扰误差有所变化，但没有随N单调改善，且仍远未解决。M从4增到8也没有让达标数增加。因此，“只增加神经元”或“只增加槽位”都还不是现成解决方案。

N变化也改变W、编码器和读出器参数量：总参数分别为67,513/126,745/263,641，不能把结果解释成只改变存储容量的因果实验。W为3N²，从64到128增大4倍，计算成本同步增长；大模型用相同100步还可能更欠训练。保持总神经元C×N不变的拓扑对照、充分训练后的容量曲线和更长历史均未完成。

## 新增Query诊断：当前关联读取还很弱

冻结三个已训练基线checkpoint，对同一段held-out历史分别用8个Query读取，`q_i=2*k_i`，不额外加噪声，延迟为0。该协议与主实验的单个带噪Query不同，不混合其绝对误差。

| 数据 | 当前读取MSE | 循环错配Query输出后的MSE | 历史平均Value参考MSE | 学生/教师Query变化幅度比 |
|---|---:|---:|---:|---:|
| 低秩背景 | 0.402534 | 0.402649 | 0.346437 | 0.0653 |
| 随机关联 | 0.638863 | 0.638291 | 0.586918 | 0.0372 |
| 唯一事件 | 0.136048 | 0.136117 | 0.103559 | 0.0230 |
| 相似Key | 0.072367 | 0.072367 | 0.000375 | 1.5462 |

变化幅度是同一历史内减去Query维均值后的输出RMS；比值先按种子计算再平均。相似Key中教师本来几乎不随Query变化，因此最后一项比值大不表示学生有效关联检索。

随机Key下，学生对Query的变化幅度只有教师约3.7%，错配Query几乎不增加误差。这更直接地表明当前学生没有形成足够强的Query选择性。但它不能区分信息是在写入时丢失、跨列时损失，还是读取器未学会利用。

历史平均Value参考对每段历史仅计算均值，完全不使用Query。上述诊断中它比当前读出更好，尤其相似Key场景。该参考理论上只需保持8维Value总和与计数；这里用教师历史直接计算，用于诊断，尚未接成独立在线学生基线。当前20%验收只与清零/打乱比较，属于弱基准；相似Key上的通过主要支持部分统计摘要可保留，不能证明任意Key–Value关联已经存储成功。

## 改进目标及顺序

### 首先证明按Key读取，而不只学习历史平均

- 为每段已写历史提供多个不同Query监督，保持写入时不可见未来Query；显式评估更换Query后答案能否正确改变。
- 加入在线平均Value基线、无Query读出基线、相同字节预算的精确窗口和线性关联记忆基线。随机Key场景应明显优于平均Value，并优于错配Query；相似Key不再作为关联检索的主要成功证据。
- 先跑单事件、2/4/8个可区分关联，再加入背景和干扰，定位最早失效环节。训练/验证/测试分离；新的确认测试使用新种子和新历史，避免反复调整到当前评估集。

### 排除欠训练和目标冲突

- 在N=64保持不变时，比较100/1000/3000步，记录固定验证集曲线，再用独立测试集确认。若增加训练显著有效，不应把原失败归为物理容量不足。
- 比较只训练主要末列attention目标，与不同权重的Value探针及三位置联合损失。探针先作为诊断，不默认要求它与主目标同等权重。
- 将延迟64/256逐步纳入训练，并明确长序列TBPTT是否切断早期写入的梯度；不能只把训练延迟加长就假设早期写入仍有监督。

### 分离写入、传播和读取瓶颈

- 冻结同一已训练阵列，单独训练更强的Query读出，判断已有状态还能否被利用；再比较固定读出条件下的不同写入/传播。
- 比较4/8/16个latent槽位；测试直接由Q与状态联合计算的读出，绕开固定4个Value的凸包限制。报告读出参数和延迟，不能把它们当作零开销。
- 将KV线性拼接与有乘性交互的关联编码比较，例如Key特征与Value的外积投影；仍将结果写入固定LIF状态，不额外藏完整历史。
- 记录每列在整个微步序列上的发放率、死神经元比例、电位分布、状态区分度与有效秩。当前JSON的activity只是最后一个微步的脉冲均值，不是整段时序发放率，不能据此断言饱和或稀疏率。
- 校准阈值、电流尺度和tau；比较占用同样N的正负双通道编码，检查带符号或亚阈值信息能否传到末列。不能把“首列有信号”当作“末列获得了信息”。

### 提高持续干扰下的选择性保持

- 在因果可用信息内，根据新颖度、历史残差等控制写入；防止每个干扰token都覆盖相同状态。
- 分区或分时间尺度保留不同事件，比较固定状态预算；后续再引入有硬预算的近期精确窗口及保护策略。
- 等待条件好、干扰条件差是写入干扰/覆盖的线索，不是已证明的唯一原因；需要训练分布、状态分布与读出外推一起排查。

### 最后建立容量曲线和真实压缩证据

- 在关联读取和训练基本稳定后，系统扫描N=32/64/128/256、历史长度、Query数量和干扰长度，并控制读取容量与充分训练预算。
- 同时比较固定N和固定总神经元C×N两种口径；改变S时保持每事件总时间一致。
- 只有当性能随N稳定改善、且不能由更强读出或更多训练解释时，才把“数量不足”作为主要证据支持的瓶颈，并选择满足误差与总内存目标的最小N。
- 在训练过的模型上验证长历史质量和读写成本，再报告状态、静态参数、临时激活及真实模型峰值。当前8-token质量测试和10000-event字节测试是两件不同的实验。
